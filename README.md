# Мониторинговый сервис

## Разработка

Нужен Node.js 24. Бэкенд должен работать на `http://127.0.0.1:8000`.

```powershell
npm ci
npm run dev
```

Откройте адрес, показанный Vite (обычно `http://localhost:5173`). Запросы `/api/*` Vite отправляет в бэкенд, убирая `/api`. Адрес для разработки задаётся в `vite.config.ts`. Пароль администратора берётся из настроек бэкенда; секреты в сборку фронтенда не добавляются.

## Docker

Фронтенд собирается через `Dockerfile`: Node.js собирает приложение, Nginx раздаёт результат. Nginx направляет `/api/*` к сервису `backend:8000` в общей Docker-сети. Обновление страницы по адресу `/devices/2` также поддерживается.

Из папки фронтенда можно собрать образ:

```powershell
docker build -t monitoring-frontend:local .
```

Для совместного запуска используйте `docker-compose.yaml` из репозитория бэкенда (`backend/dev`). Укажите в его `.env` путь `FRONTEND_CONTEXT` к этой папке; в текущем расположении это `../../Frontend/monitoring-service` относительно Compose.

Из корня репозитория бэкенда:

```powershell
docker compose up -d --build
```

Сайт будет доступен на `http://localhost:8080`. После изменений: `docker compose up -d --build frontend`.

## Подключение к API

- Вход, выход и обработка истёкшей сессии (`401`).
- Список устройств с поиском, пагинацией и счётчиками с сервера.
- Создание устройства, переход в карточку по ID, переименование и замена токена.
- Метрики, диски и исходные состояния служб без подмены неизвестного состояния на `stopped`.
- История за 5 и 15 минут, 1, 6, 24 часа или выбранный период. По умолчанию — последние 15 минут. Даты выбираются в локальном времени и отправляются с часовым поясом.
- Наведение на измерение показывает время начала интервала и значение показателя. Значение в истории усредняется бэкендом за интервал группировки.
- Список и карточка обновляются каждые 30 секунд. Пропуски истории отображаются разрывами, отсутствующие значения — как отсутствие данных.

Разрыв линии возникает при паузе больше `max(ONLINE_TIMEOUT_SECONDS, 1.5 × step_seconds)`. Это визуальная оценка по времени сгруппированных измерений, а не точная история статусов устройства. `null` всегда разрывает линию. Compose передаёт `ONLINE_TIMEOUT_SECONDS` из `.env` бэкенда при сборке фронтенда (по умолчанию 180 секунд). После изменения настройки выполните `docker compose up -d --build frontend`. Для локальной разработки можно задать `VITE_ONLINE_TIMEOUT_SECONDS` в `.env.local` и перезапустить Vite.

При отдельной сборке образа: `docker build --build-arg ONLINE_TIMEOUT_SECONDS=180 -t monitoring-frontend:local .`. В готовом образе порог зафиксирован на этапе сборки; изменение окружения уже запущенного Nginx не меняет его.

## Проверка

```powershell
npm run build
npm test
npm run lint
```

После запуска проверьте вход, создание устройства с новым токеном, открытие его карточки, переименование, смену токена и выход. Запустите агент с этим токеном и `SERVER_URL=http://localhost:8080/api`, убедитесь, что появляются метрики. С другого компьютера вместо `localhost` нужен IP сервера и публикация порта сайта на сетевом интерфейсе.
